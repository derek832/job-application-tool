# Requirements Document

## Introduction

The LinkedIn Job Automator is a locally-hosted, mostly-automated job application system that runs on the user's personal computer via Docker. It combines a Chrome extension control panel, Playwright-driven browser automation, Claude API for AI analysis, and Google Docs integration to search LinkedIn for relevant jobs, score them against the user's resume and goals, tailor application materials, and submit applications — with human-in-the-loop escalation via SMS for exceptions that require judgment or manual input.

The system operates on a Monday–Friday schedule, targeting jobs posted in the last 24 hours. It supports both LinkedIn Easy Apply and external job sites (via visual form parsing). All job state is persisted in a local database to prevent re-processing.

---

## Glossary

- **Automator**: The core orchestration service running inside Docker on the user's local machine.
- **Extension**: The Chrome browser extension that serves as the user-facing control panel.
- **Job_Record**: A persisted entry in the State_DB representing a discovered job and its processing status.
- **State_DB**: The local SQLite (or equivalent) database that tracks all discovered jobs and their lifecycle states.
- **Fit_Score**: A numeric score (0–100) produced by the Claude API representing how well a job matches the user's resume and goals.
- **Goals_Profile**: A user-defined configuration specifying target roles, preferred industries, deal-breakers, stretch role tolerance, and other job-seeking preferences.
- **Resume_Base**: The single canonical resume document stored in Google Docs that serves as the source for all tailored applications.
- **Tailored_Resume**: A version of Resume_Base modified by the Claude API to optimize for a specific job description and ATS keywords.
- **ATS**: Applicant Tracking System — automated software used by employers to filter resumes.
- **Easy_Apply**: LinkedIn's native one-click or short-form application flow.
- **External_Apply**: A job application hosted on a third-party site outside LinkedIn, requiring navigation to an external URL.
- **Vision_Agent**: The Playwright + Claude Vision component that visually parses and fills external application forms.
- **Human_Queue**: The list of jobs or actions awaiting manual user review or input.
- **SMS_Gateway**: The Gmail-to-carrier SMS gateway used to send text message notifications to the user's phone.
- **Notification_Trigger**: A defined condition that causes the Automator to pause and alert the user via SMS.
- **Scheduler**: The cron-based component inside Docker that initiates job search runs on weekdays.
- **Search_Config**: The user-defined LinkedIn search parameters stored in the Extension.
- **Good_Fit**: A job with a Fit_Score at or above the good-fit threshold (default: 75).
- **Stretch_Role**: A job with a Fit_Score between the stretch threshold and the good-fit threshold (default: 50–74).
- **Skip**: A job with a Fit_Score below the stretch threshold (default: below 50) or matching a deal-breaker.
- **Google_Apps_Script**: The server-side scripting platform used to programmatically update Resume_Base in Google Docs and export it as PDF.
- **Cover_Letter**: An optional application document generated by the Claude API for jobs that require one.

## Requirements

### Requirement 1: Scheduled Job Search

**User Story:** As a job seeker, I want the system to automatically search LinkedIn for new job postings on weekdays, so that I don't have to manually check LinkedIn every day.

#### Acceptance Criteria

1. THE Scheduler SHALL initiate a job search run once per weekday (Monday through Friday) at a user-configurable time.
2. WHEN a job search run is initiated, THE Automator SHALL query LinkedIn using the active Search_Config.
3. THE Search_Config SHALL support the following parameters: keywords (comma-separated), location, job type (full-time, part-time, contract, internship), experience level (entry, associate, mid-senior, director, executive), remote preference (on-site, remote, hybrid), and a 24-hour recency filter.
4. WHEN a job listing is returned by LinkedIn, THE Automator SHALL check the State_DB to determine whether a Job_Record already exists for that listing's unique identifier.
5. IF a Job_Record already exists for a listing, THEN THE Automator SHALL skip that listing without re-processing it.
6. WHEN a new job listing is discovered, THE Automator SHALL create a Job_Record in the State_DB with status "discovered" and store the job title, company, location, LinkedIn URL, and timestamp.

---

### Requirement 2: Job Description Extraction

**User Story:** As a job seeker, I want the system to extract the full job description from each new listing, so that it can be analyzed for fit.

#### Acceptance Criteria

1. WHEN a Job_Record has status "discovered", THE Automator SHALL navigate to the job's LinkedIn URL using Playwright and extract the full job description text.
2. WHEN the job description is successfully extracted, THE Automator SHALL update the Job_Record with the description text and set status to "extracted".
3. IF the job description cannot be extracted after 3 attempts, THEN THE Automator SHALL set the Job_Record status to "extraction_failed" and add the job to the Human_Queue.
4. WHEN a job is added to the Human_Queue due to extraction failure, THE Automator SHALL send an SMS notification to the user with the job title, company, and LinkedIn URL.

---

### Requirement 3: Fit Scoring

**User Story:** As a job seeker, I want each job to be scored against my resume and goals, so that I can focus on the most relevant opportunities.

#### Acceptance Criteria

1. WHEN a Job_Record has status "extracted", THE Automator SHALL submit the job description, Resume_Base content, and Goals_Profile to the Claude API for fit analysis.
2. THE Claude API SHALL return a Fit_Score between 0 and 100 and a brief rationale (maximum 200 words) explaining the score.
3. WHEN the Fit_Score is at or above the good-fit threshold, THE Automator SHALL classify the job as "Good_Fit" and set the Job_Record status to "approved_for_apply".
4. WHEN the Fit_Score is between the stretch threshold and the good-fit threshold (inclusive), THE Automator SHALL classify the job as "Stretch_Role" and add it to the Human_Queue for user review.
5. WHEN the Fit_Score is below the stretch threshold, THE Automator SHALL classify the job as "Skip" and set the Job_Record status to "skipped".
6. WHEN a job description contains a term matching any entry in the Goals_Profile deal-breakers list, THE Automator SHALL classify the job as "Skip" regardless of Fit_Score.
7. WHEN a Stretch_Role is added to the Human_Queue, THE Automator SHALL send an SMS notification containing the job title, company, Fit_Score, and a short rationale summary.
8. THE Automator SHALL store the Fit_Score and rationale in the Job_Record.
9. THE good-fit threshold SHALL default to 75 and be configurable by the user via the Extension.
10. THE stretch threshold SHALL default to 50 and be configurable by the user via the Extension.

---

### Requirement 4: Goals Profile Configuration

**User Story:** As a job seeker, I want to define my job-seeking goals and preferences, so that the system applies to jobs that align with my career objectives.

#### Acceptance Criteria

1. THE Extension SHALL provide a Goals_Profile editor where the user can define: target job titles (list), preferred industries (list), preferred company sizes (list), geographic preferences (list), minimum acceptable salary (optional integer), deal-breaker keywords (list), openness to stretch roles (boolean), and a free-text "career objective" statement.
2. WHEN the user saves the Goals_Profile, THE Extension SHALL persist it to the Automator's configuration store and confirm the save was successful.
3. THE Automator SHALL include the full Goals_Profile in every Claude API fit analysis request.
4. IF the Goals_Profile has not been configured, THEN THE Automator SHALL pause all job search runs and notify the user via the Extension that configuration is required before the system can operate.

---

### Requirement 5: Resume Tailoring

**User Story:** As a job seeker, I want my resume tailored to each job's ATS keywords before applying, so that my application has the best chance of passing automated screening.

#### Acceptance Criteria

1. WHEN a Job_Record has status "approved_for_apply", THE Automator SHALL submit the job description and Resume_Base content to the Claude API requesting an ATS-optimized tailored version.
2. THE Claude API SHALL return a Tailored_Resume that preserves all factual content from Resume_Base while incorporating relevant keywords from the job description.
3. THE Claude API SHALL NOT fabricate experience, skills, or credentials not present in Resume_Base.
4. WHEN the Tailored_Resume is generated, THE Automator SHALL update Resume_Base in Google Docs via Google_Apps_Script with the tailored content.
5. WHEN the Google Docs update is complete, THE Automator SHALL trigger Google_Apps_Script to export the document as a PDF.
6. THE Automator SHALL store the exported PDF path in the Job_Record.
7. IF the Google Docs update or PDF export fails, THEN THE Automator SHALL retry up to 3 times before setting the Job_Record status to "resume_failed" and adding the job to the Human_Queue.
8. WHEN a resume tailoring failure is added to the Human_Queue, THE Automator SHALL send an SMS notification with the job title and company.

---

### Requirement 6: LinkedIn Easy Apply Automation

**User Story:** As a job seeker, I want the system to automatically submit Easy Apply applications on LinkedIn, so that I can apply to many jobs without manual effort.

#### Acceptance Criteria

1. WHEN a Job_Record has status "approved_for_apply" and the job is marked as Easy_Apply, THE Automator SHALL initiate the Easy Apply flow using Playwright.
2. THE Automator SHALL attach the Tailored_Resume PDF when the Easy Apply form requests a resume upload.
3. THE Automator SHALL auto-fill standard Easy Apply fields (name, email, phone, location, work authorization) using values from the user's profile configuration.
4. WHEN the Easy Apply form contains a question not covered by the user's profile configuration, THE Automator SHALL add the job to the Human_Queue and send an SMS notification with the job title, company, and the specific unanswered question.
5. WHEN the Easy Apply form requests a cover letter, THE Automator SHALL invoke the Claude API to generate a Cover_Letter tailored to the job description and Goals_Profile, then attach it.
6. WHEN all Easy Apply form fields are filled, THE Automator SHALL submit the application and set the Job_Record status to "applied".
7. IF the Easy Apply submission fails, THEN THE Automator SHALL retry once before setting the Job_Record status to "apply_failed" and adding the job to the Human_Queue.
8. WHEN an Easy Apply failure is added to the Human_Queue, THE Automator SHALL send an SMS notification with the job title, company, and error description.

---

### Requirement 7: External Site Visual Application

**User Story:** As a job seeker, I want the system to attempt applications on external job sites using visual form parsing, so that non-Easy Apply jobs are also handled automatically where possible.

#### Acceptance Criteria

1. WHEN a Job_Record has status "approved_for_apply" and the job is marked as External_Apply, THE Automator SHALL navigate to the external application URL using Playwright.
2. THE Vision_Agent SHALL capture a screenshot of the application form and submit it to the Claude API with a prompt requesting identification of all visible form fields and their labels.
3. THE Vision_Agent SHALL map identified form fields to values from the user's profile configuration and Tailored_Resume.
4. THE Vision_Agent SHALL fill each identified form field using Playwright interactions (click, type, select).
5. WHEN the Vision_Agent encounters a form field it cannot confidently map to a known value, THE Automator SHALL add the job to the Human_Queue and send an SMS notification with the job title, company, and a description of the unrecognized field.
6. WHEN the Vision_Agent detects a CAPTCHA on the application form, THE Automator SHALL immediately add the job to the Human_Queue and send an SMS notification with the job title, company, and the external URL.
7. WHEN the Vision_Agent detects a salary expectation field, THE Automator SHALL check the Goals_Profile for a minimum acceptable salary value; IF a value is configured, THE Vision_Agent SHALL enter it; IF no value is configured, THE Automator SHALL add the job to the Human_Queue and send an SMS notification.
8. WHEN the Vision_Agent detects a multi-step form with more than 3 pages, THE Automator SHALL add the job to the Human_Queue and send an SMS notification with the job title, company, and external URL.
9. WHEN all form fields are filled and no escalation conditions are met, THE Vision_Agent SHALL submit the form and set the Job_Record status to "applied".
10. IF the external form submission fails or the Vision_Agent cannot determine submission success, THEN THE Automator SHALL set the Job_Record status to "apply_failed" and add the job to the Human_Queue.

---

### Requirement 8: Human-in-the-Loop Queue

**User Story:** As a job seeker, I want a clear queue of jobs and actions that need my attention, so that I can review exceptions without losing track of them.

#### Acceptance Criteria

1. THE Extension SHALL display the Human_Queue as a list of pending items, each showing: job title, company, LinkedIn URL, reason for escalation, and timestamp added.
2. WHEN the user resolves a Human_Queue item (approves, rejects, or manually completes it), THE Extension SHALL update the corresponding Job_Record status and remove the item from the Human_Queue.
3. THE Extension SHALL allow the user to approve a Stretch_Role for application, which SHALL set the Job_Record status to "approved_for_apply".
4. THE Extension SHALL allow the user to reject any job in the Human_Queue, which SHALL set the Job_Record status to "rejected_by_user".
5. THE Extension SHALL allow the user to mark a Human_Queue item as "manually_applied", which SHALL set the Job_Record status to "applied".
6. THE Automator SHALL process Human_Queue approvals and resume the application workflow for the approved job within 5 minutes of the user's action.
7. THE Extension SHALL display a badge count on its toolbar icon showing the number of pending Human_Queue items.

---

### Requirement 9: SMS Notifications

**User Story:** As a job seeker, I want to receive SMS alerts when the system needs my input, so that I can respond promptly without monitoring a dashboard.

#### Acceptance Criteria

1. THE Automator SHALL send SMS notifications via the Gmail API (OAuth2) using the carrier's email-to-SMS gateway address configured by the user.
2. THE user SHALL configure the SMS gateway address (e.g., 5307558669@vtext.com) in the Extension settings.
3. WHEN a Notification_Trigger condition is met, THE Automator SHALL compose and send an SMS message within 60 seconds of detecting the condition.
4. THE SMS message SHALL include: a brief description of the issue, the job title and company name, and a short action prompt (e.g., "Open extension to review").
5. THE SMS message SHALL be 160 characters or fewer to ensure single-message delivery.
6. IF the Gmail API send fails, THEN THE Automator SHALL retry up to 3 times with [5s, 15s, 30s] backoff before logging the failure and continuing.
7. THE Automator SHALL NOT send more than 10 SMS notifications within any 1-hour window to prevent notification flooding.
8. THE Automator SHALL authenticate with the Gmail API using OAuth2 with the `gmail.send` scope. The OAuth2 refresh token is stored locally in `data/gmail_token.json` and refreshed automatically.

---

### Requirement 10: State Persistence and Job Tracking

**User Story:** As a job seeker, I want all job processing state persisted locally, so that the system never re-processes a job and I have a full history of my applications.

#### Acceptance Criteria

1. THE State_DB SHALL persist all Job_Records across Automator restarts.
2. EACH Job_Record SHALL store: unique job identifier, job title, company name, location, LinkedIn URL, external apply URL (if applicable), apply type (Easy_Apply or External_Apply), Fit_Score, fit rationale, Job_Record status, tailored resume PDF path, timestamps for each status transition, and any error messages.
3. THE valid Job_Record status values SHALL be: discovered, extracted, extraction_failed, scored, approved_for_apply, skipped, rejected_by_user, resume_failed, applying, apply_failed, applied, manually_applied.
4. THE Extension SHALL display a searchable, filterable job history table showing all Job_Records and their current statuses.
5. THE Extension SHALL display summary statistics: total jobs discovered, total applied, total skipped, total pending human review, and application success rate (applied / approved_for_apply).
6. WHEN the State_DB file is absent on startup, THE Automator SHALL initialize a new empty State_DB.
7. THE Automator SHALL perform a State_DB backup to a user-configured local directory once per day.

---

### Requirement 11: Chrome Extension Control Panel

**User Story:** As a job seeker, I want a Chrome extension as my primary control panel, so that I can configure, monitor, and control the system from my browser without opening a separate application.

#### Acceptance Criteria

1. THE Extension SHALL communicate with the Automator via a local HTTP API exposed on a configurable port (default: 7432).
2. THE Extension SHALL display the current system status: running, paused, idle, or error.
3. THE Extension SHALL provide a "Run Now" button that triggers an immediate job search run outside the scheduled time.
4. THE Extension SHALL provide a "Pause / Resume" toggle that stops or resumes all scheduled and manual runs.
5. THE Extension SHALL provide a Search_Config editor where the user can set all LinkedIn search parameters defined in Requirement 1.
6. THE Extension SHALL provide a Goals_Profile editor as defined in Requirement 4.
7. THE Extension SHALL provide a Profile Configuration section where the user can enter personal application data: full name, email address, phone number, location, work authorization status, LinkedIn profile URL, and answers to common application questions.
8. THE Extension SHALL provide a Settings section for: Claude API key, Gmail credentials, SMS gateway address, Google Docs resume document ID, scheduled run time, good-fit threshold, stretch threshold, and local backup directory path.
9. WHEN the Automator is unreachable, THE Extension SHALL display a clear error state and the last known connection timestamp.

---

### Requirement 12: Docker-Based Local Orchestration

**User Story:** As a job seeker, I want the system to run entirely on my personal computer via Docker, so that my credentials and data never leave my machine.

#### Acceptance Criteria

1. THE Automator SHALL be packaged as a Docker Compose application with all dependencies (Playwright, database, scheduler) included.
2. THE Docker Compose configuration SHALL mount a local host directory for State_DB and resume PDF storage so data persists across container restarts.
3. THE Docker Compose configuration SHALL accept environment variables for all secrets (Claude API key, Gmail credentials, Google OAuth tokens) so secrets are never baked into the image.
4. THE Automator SHALL expose its local HTTP API only on localhost (127.0.0.1) and SHALL NOT bind to external network interfaces.
5. WHEN the Docker container starts, THE Automator SHALL perform a self-check verifying connectivity to the Claude API, Gmail, and Google Docs, and SHALL report any failures via the Extension status display.
6. THE Automator SHALL log all actions, decisions, and errors to a rotating log file accessible from the mounted host directory.

---

### Requirement 13: Cover Letter Generation

**User Story:** As a job seeker, I want the system to generate a tailored cover letter when one is required, so that I don't have to write one manually for every application.

#### Acceptance Criteria

1. WHEN a cover letter is required by an application form, THE Automator SHALL submit the job description, Tailored_Resume content, and Goals_Profile career objective to the Claude API requesting a cover letter.
2. THE generated Cover_Letter SHALL be addressed to the hiring team, reference the specific job title and company name, highlight 2–3 relevant qualifications from the Tailored_Resume, and be 250–400 words in length.
3. THE Cover_Letter SHALL NOT contain fabricated experience or credentials not present in Resume_Base.
4. THE Automator SHALL store the generated Cover_Letter text in the Job_Record.
5. WHEN a cover letter is generated, THE Automator SHALL attach it to the application as a PDF or plain text as required by the form.

---

### Requirement 14: Google Docs Resume Integration

**User Story:** As a job seeker, I want my resume managed in Google Docs so that I have a human-readable, editable master copy that the system can update and export.

#### Acceptance Criteria

1. THE Automator SHALL use Google_Apps_Script to read the current content of Resume_Base from the configured Google Docs document.
2. WHEN a Tailored_Resume is generated, THE Automator SHALL use Google_Apps_Script to overwrite the Google Docs document content with the tailored version.
3. WHEN the Google Docs document is updated, THE Automator SHALL use Google_Apps_Script to export the document as a PDF and save it to the local mounted Docker volume.
4. THE Automator SHALL restore Resume_Base to its original content after each application by re-writing the pre-tailoring snapshot stored in the Job_Record.
5. IF Google_Apps_Script returns an authorization error, THEN THE Automator SHALL pause all application runs and notify the user via the Extension and SMS to re-authenticate.

---

### Requirement 15: Notification Triggers

**User Story:** As a job seeker, I want the system to notify me for all conditions that require human judgment, so that I never miss an application that needs my attention.

#### Acceptance Criteria

1. THE Automator SHALL send an SMS notification and add the job to the Human_Queue for each of the following Notification_Trigger conditions:
   a. A CAPTCHA is detected on any application form.
   b. A salary expectation field is detected and no minimum salary is configured in the Goals_Profile.
   c. A cover letter is required and cover letter generation fails.
   d. An Easy Apply form contains an unanswered question not in the user's profile configuration.
   e. An external form has more than 3 pages.
   f. The Vision_Agent cannot confidently identify a form field.
   g. A job is classified as a Stretch_Role.
   h. Any automated step fails after all retries are exhausted.
   i. The Fit_Score returned by the Claude API is exactly at a threshold boundary (within ±2 points of either threshold).
2. THE Automator SHALL log every Notification_Trigger event with a timestamp, job identifier, and trigger reason in the State_DB.
